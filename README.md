# Thermal Solver

Решатель стационарного уравнения теплопроводности в 3D

## Описание

Рассматривается стационарное уравнение теплопроводности без источников в прямоугольной области размером `Lx * Ly * Lz`. Температуры `Tx, Ty, Tz` на границах фиксированы. Программа поддерживает три режима работы:

- `cg` - только метод сопряженных градиентов без предобусловливания
- `mg` - cg с предобусловливанием (см. ниже)
- `mg_gpu` - то же, что `mg`, но предобусловливатель на GPU

Аргументы:
```
OMP_NUM_THREADS=5 OMP_WAIT_POLICY=active ./thermal Nx Ny Nz Tx1 Tx2 Ty1 Ty2 Tz1 Tz2 mg_gpu 100 1e-7 Lx Ly Lz
```
`Nx, Ny, Nz` - количество ячеек в сетке по осям

## Дискретизация

### Схема

На сетке `(x_i, y_j, z_k) = (i·h_x, j·h_y, k·h_z)`:

$$\frac{T_{i+1,j,k} - 2T_{i,j,k} + T_{i-1,j,k}}{h_x^2} + \frac{T_{i,j+1,k} - 2T_{i,j,k} + T_{i,j-1,k}}{h_y^2} + \frac{T_{i,j,k+1} - 2T_{i,j,k} + T_{i,j,k-1}}{h_z^2} = 0$$

Узел `(i,j,k)` связан с шестью соседями (по 2 на каждую координату)



Коэффициенты:

- центр: `-2/h_x² - 2/h_y² - 2/h_z²`
- по x: `+1/h_x²`
- по y: `+1/h_y²`
- по z: `+1/h_z²`

Порядок аппроксимации — `O(h²)`





## Предобусловливание

Вместо `Ax = b` решаем `M⁻¹Ax = M⁻¹b`



## Геометрический многосеточный метод

Ошибка решения имеет компоненты разных масштабов:

- Высокие частоты видны на мелкой сетке, но не видны на грубой
- Низкие частоты видны только на грубой сетке

Сглаживатель эффективно гасит высокие частоты. Идея в том, чтобы увеличить шаг сетки таким образом, чтобы низкие частоты относительно нового шага стали высокими







### Иерархия сеток

Строится делением пополам:

$$N^{(\ell+1)} = \frac{N^{(\ell)} + 1}{2}, \quad h^{(\ell+1)} = 2 h^{(\ell)}$$

Останавливается, когда `N = 3`

`N - 1` должно быть степенью двойки.



## Сглаживатель

### Weighted Jacobi

Итерация:

$$u_k \leftarrow u_k + \omega \frac{f_k - (Au)_k}{A_{kk}}$$

Параметр `ω = 2/3`

Число итераций фиксированное - 3

Этот метод сам по себе тоже итерационный решатель. Однако точная сходимость здесь не обязательна - достаточно убрать высокие частоты.


## Операторы переноса

### Перенос на грубую сетку

Для перехода с мелкой сетки на грубую используется свертка с ядром  [1/4 1/2 1/4] $$\otimes$$ [1/4 1/2 1/4] $$\otimes$$ [1/4 1/2 1/4] со strides = 2


### Перенос на мелкую сетку

Deconvolution с ядром  [1/2 1 1/2] $$\otimes$$ [1/2 1 1/2] $$\otimes$$ [1/2 1 1/2], strides = 2. Реализовано как разделение всех узлов ядра на 4 типа:

| Тип | Позиция | Значение |
|-----|---------|------|
| Чётно-чётно-чётный | `(2i_c, 2j_c, 2k_c)` | копия грубого узла |
| Одна нечётная координата | середина ребра | `1/2 · (2 грубых)` |
| Две нечётные | центр грани | `1/4 · (4 грубых)` |
| Три нечётные | центр ячейки | `1/8 · (8 грубых)` |



## V-цикл

```
v_cycle(lvl):
    если lvl == last:
        solve_3x3(lvl)
        return

    smooth(lvl, nu1)
    conv3d(lvl)
    u_{lvl+1} = 0
    v_cycle(lvl + 1)
    deconv3d(lvl)
    smooth(lvl, nu2)
```

Весь V-цикл работает в `float` точности. На точность решения всей задачи это не влияет, зато появляется возможность GPU ускорения

### GPU

В режиме `mg_gpu` на каждом уровне, где `Nx * Ny * Nz > gpu_threshold`, операции выполняются на GPU (если доступно). Вычислительные ядра сверток на самом деле полностью взяты из моего другого проекта и не слишком оптимизированы для конкретно этой задачи. Ощутимый эффект начинается на сетках около `513 × 513 × 513`.

### Грубейший уровень и solve_3x3

На наименьшей сетке применяется метод Гаусса–Зейделя. На не слишком анизотропных сетках сходится меньше чем за 10 итераций и на общую скорость не влияет
